## 1. 研究陈述

> 真实环境中有大量受电端（Sink）不支持连续调功（PPS），而供电端（Source）无法获知或信任它们的热管理能力。针对这一问题，本研究提出一种**由 Source 单端主导、兼容 USB PD 2.0 的动态 PDO 游标机制**：
> - **A（状态感知）**：Source 利用自身可观测的电气与热信号，以及 PD 协议可获取的设备信息，估计当前状态。
> - **B（风险预测）**：用物理引导、动作条件化、带校准不确定性的神经网络，超前预测开放不同 PDO 子集 $\mathcal{S}(k)$ 时，Source、接口/线缆与 Sink 各热节点的温度风险上界。
> - **C（游标截断）**：按风险阈值，在一条排好序的 PDO 轴上截断，生成符合规范的 Source_Capabilities，动态限制 Sink 可申请的功率上界。
> - **安全兜底**：一层基于物理上界的运行时兜底，越界时立即接管。
>
> 目标：在不改硬件、不依赖 Sink 配合的前提下，在机会约束 P(过温) ≤ α 下最小化充电速度损失，实验上逼近"安全–速度"帕累托前沿。

## 2. 背景

### 2.1 USB PD 协商流程（简化，细节【需核实】）

1. Source 发送 Source_Capabilities 消息，内含若干 PDO（Power Data Object），最多 7 个。
2. Sink 发送 Request，选择其中一个 PDO（按位置编号），并给出申请电流。
3. Source 回复 Accept；电源切换完成后发送 PS_RDY，形成显式合约。
4. 合约期间，Source 可以随时重新发送 Source_Capabilities，Sink 必须重新发送 Request（即重新协商）。如果 Sink 处理失败，可能触发 Hard Reset，VBUS 会掉电。

PDO 规则（全部【需核实】，由 T0.2 核实）：

- 第一个 PDO 必须是 vSafe5V 的 Fixed PDO。
- Fixed PDO 按电压升序排列。
- 同类型、同电压只能有一个 PDO（取该电压下的最大电流）。
- Fixed PDO 的最大电流字段单位是 10 mA。
- Power Rules 规定了不同额定功率（PDP）下必须提供的电压/电流组合。例如 45W：5V/3A、9V/3A、15V/3A、20V/2.25A。其中 15V/3A 和 20V/2.25A 功率相同。
- PD 2.0 已有 Get_Sink_Cap 和 Discover Identity（Sink 可选支持）。
- PD 3.0 的 Status 消息含 Internal Temp 和 Temperature Status 字段；Alert 消息可报告过温（OTP）事件。

### 2.2 现状与痛点

- PPS 在 PD 3.0 引入，可以连续调压调流，但大量存量 Sink 只支持 Fixed PDO。
- Sink 的热管理对 Source 不可知、不可信：有的有 JEITA 类降流，有的没有；有的阈值偏高、反应偏慢。
- 现有 Source 侧做法主要有三类：固定降额、反应式降功率（温度到阈值后降）、多口充电器的动态功率分配。它们多数是反应式的，且主要保护 Source 自身。

### 2.3 本研究要做的

在 Source 侧，只用 PD 规范已有的机制，**预测性地**限制 Sink 可申请的最大 PDO，使各热节点满足温度约束，同时让充电速度损失最小。

## 3. 问题设定

### 3.1 热节点

| 节点 | 符号 | 部署时能否观测 | 说明 |
|---|---|---|---|
| Source 内部 | `t_src` | 能（Source 内 NTC） | 直接测量 |
| 接口/线缆 | `t_con` | 能，前提是硬件在 Source 端插座附近有 NTC | 线缆远端和 Sink 端插座测不到 |
| Sink 电芯 | `t_bat` | 不能。Sink 支持 PD 3.0 Status 时可得到粗略值【待定 Q4】 | 实验中用系统接口或热电偶测，作为标签 |
| Sink 表面 | `t_skin` | 不能 | 实验中用热电偶或红外测，作为标签 |

### 3.2 威胁模型【已定】

Source 无法获知、也无法信任 Sink 的热管理能力。Sink 可能是以下任一类：

- (a) 没有热管理，并且贪婪地申请最高功率；
- (b) 有 JEITA 类分段降流；
- (c) 有激进的自主热管理（例如按表面温度降功率）。

Source 必须对所有类型都安全，同时尽量不损失 (b)、(c) 类设备的速度（避免"双重节流"）。

### 3.3 约束【已定】

- 不改硬件：Source 只做固件升级，Sink 不做任何修改。
- 不依赖 Sink 配合。
- 严格遵守 USB PD 规范。

### 3.4 形式化

- **控制周期**：Δ（默认 10 s），时间步 k。
- **PDO 轴**：有序列表 p_1, …, p_N，其中 p_1 = vSafe5V。开放集合 S(c) = {p_1, …, p_c}，c ∈ {1, …, N} 称为游标。
- **Sink 选择规则**：g(S) ∈ S，Source 不知道这个规则。
- **观测**：o_k，只包含部署时可得的特征（见 4.1 白名单）。
- **单个 PDO 的风险**：r_j(p) 表示"若 Sink 以 PDO p 的满功率充电，节点 j 在未来时域 H 内最高温度的 (1−α) 上分位数（已校准）"。
- **集合风险**：R_j(S) = max_{p∈S} r_j(p)。
- **安全条件**：对每个节点 j，R_j(S(c)) ≤ T_lim,j − m_j，其中 m_j 是裕量。
- **速度损失**：L = ∫ max(0, P_dem(t) − P_del(t)) dt。P_dem 是不加限制时 Sink 会吸收的功率，P_del 是实际交付功率。另一个口径：充到 80% 的时间比不加限制时多出多少。
- **优化目标**：在每个节点满足 P(T_j > T_lim,j) ≤ α 的约束下，最小化 L。

### 4.2 模块 B：风险预测器【已定：灰箱 + 动作条件化 + 分位数 + conformal】

#### 输入
- 历史窗口：过去 W 秒的白名单特征（默认 W = 600 s，1 Hz 采样，可降采样到 0.1 Hz）。
- 候选的未来输入功率序列 u_{k:k+H}（默认 H = 300 s）。
  - 推理时，评估 PDO p 的风险用最坏情况：u 恒等于 P(p) = V_p × I_p,max。
  - 训练时，u 用日志里真实发生的未来功率。
- 静态特征（如果可用）：设备类别、`sink_caps`、`vid`/`pid` 的嵌入。

#### 输出
对每个节点 j 和每个分位数 q ∈ {0.5, 0.9, 0.95, 0.99}，预测 [k, k+H] 内的最高温度。

#### 物理骨架（集总热网络）

Sink 用两节点（电芯 b、外壳 sh），接口用一节点（c）：

```
C_b  dT_b/dt  = Q_b(u)  − (T_b − T_sh)/R_bs
C_sh dT_sh/dt = Q_cv(u) + (T_b − T_sh)/R_bs − (T_sh − T_amb)/R_sa
C_c  dT_c/dt  = Q_c(u)  − (T_c − T_amb)/R_ca
```

- Q_b 是电芯产热，Q_cv 是 Sink 内转换损耗，Q_c 是接口/线缆的 I²R 产热。
- Source 节点同理，产热为 Source 转换损耗。由于可以直接观测，也可以只用纯数据驱动的预测器。
- **能量上界**：电池处于充电状态时，Q_b + Q_cv ≤ u。

#### 神经网络的作用
1. 编码器（例如 GRU）读取历史窗口，输出：
   - 当前隐状态估计 T̂_b(k)、T̂_sh(k)（部署时测不到，必须估计）；
   - 热参数 R_bs、R_sa、C_b、C_sh（用 softplus 保证为正）；
   - 产热参数化的系数。
2. 产热项用**对 u 单调不减的参数化形式**，例如 Q = a·u² + b·u，且 a, b ≥ 0。
3. 用以上参数把 ODE 在时域 H 内向前积分，取各节点最高温度，得到中位数预测。
4. 高分位数 = 中位数 + 非负增量。增量**不依赖 u**，或对 u 只使用非负权重。

这样，预测温度对 u 单调不减由结构保证：系统是线性的，节点间耦合为正（Metzler 矩阵），输入对 u 单调。单元测试必须验证这一点。

#### 损失函数
- 各分位数的 pinball loss，作用在有标签的节点（`t_bat`、`t_skin`、`t_con`、`t_src`）的未来最高温度上。
- 可选：对整条温度轨迹的辅助损失。

#### 校准
- 用单侧 CQR（conformalized quantile regression）在校准集上校准 (1−α) 上界。
- 校准集按 `device_id` 划分。
- 可选：按设备类别分组校准（Mondrian conformal）。

#### 对比的模型族
| 编号 | 模型 | 说明 |
|---|---|---|
| M0 | 纯 RC | 每个设备类别拟合一组参数，从插入时刻开环仿真，残差做 conformal |
| M1 | 纯黑盒 | GRU/TCN，不加物理结构和单调约束 |
| M2 | 灰箱（本文方法） | 如上 |

#### 关于不可观测节点
部署时 Sink 节点是开环估计，误差会随时间累积。评估时必须区分"见过的设备类型"和"没见过的设备"（见 T1.4 的数据划分）。

#### 部署目标（软约束）
模型能做 int8 量化，能在 Cortex-M4 级 MCU 上运行。在 T2.10 中实测。

### 4.3 模块 C：游标映射【已定】

每个控制周期执行：

1. **候选 PDO 列表**：从 Source 的能力配置（符合 Power Rules）得到。
2. **构造排序轴**：
   - 按功率 P(p) = V × I_max 升序排序；
   - 功率相同时，按 B 预测的风险 r(p) 升序排；
   - 删除被支配的 PDO：如果存在 q 满足 s(q) ≥ s(p) 且 r(q) ≤ r(p)，且至少一项严格成立，则 p 被支配。这里 s(p) = min(P(p), P̂_dem)，P̂_dem 是需求估计。
   - **vSafe5V 永不删除**。
3. **计算截断点**：对 c = 1…N 计算 R_j(S(c)) = max_{p∈S(c)} r_j(p)，k* = 满足"对所有 j 都有 R_j(S(c)) ≤ T_lim,j − m_j"的最大 c。没有满足的 c 时，令 k* = 1。
4. **滞回**：
   - k* < 当前游标：立即下调。
   - k* > 当前游标：只有同时满足以下三条才上调：在额外裕量 δ 下仍然安全；距上次变更 ≥ T_dwell；每次最多上调 1 档。
5. **生成消息**：由 S(k*) 生成 Source_Capabilities，按电压升序排列，并通过合规校验器。
6. **发送条件**：只有与当前广播内容不同时才发送。

**可选变体 C-PB（功率预算游标）**：游标是连续的功率预算 P_cap。每个 PDO 的电流设为 min(I_max, floor(P_cap / V / 10mA) × 10mA)。电流低于 `min_pdo_current`（可配置）的 PDO 不广播。

**安全评估和速度评估的分工**：安全评估用最坏情况（Sink 吸收 PDO 的满功率）；速度评估用需求估计 P̂_dem。

### 4.4 安全兜底层（Simplex）【已定】

任一规则触发，就覆盖 C 的输出：

| 规则 | 触发条件 | 动作 |
|---|---|---|
| S1 | `t_src` ≥ T_lim,src − m_hard | 游标降到 1，保持 ≥ T_hold |
| S2 | `t_con` ≥ T_lim,con − m_hard | 游标降到 1，保持 ≥ T_hold |
| S3 | 能量上界检查：用保守的 RC 参数（种群包络中最差的 R、最小的 C），假设全部输入功率都变成 Sink 热量，预测 H 内电芯温度上界 > T_lim,bat | 游标降到能通过该检查的最大档 |
| S4 | 收到 Sink 的 PD 3.0 Alert（OTP），或 Status 显示过温（需 Q4 批准） | 游标降到 1 |
| S5 | B 的输入异常（NaN、传感器故障）或推理失败 | 退回静态保守游标 `c_fallback` |

- **恢复**：保持时间到了以后，把控制权交还 C，并按滞回规则逐级上调。
- **日志**：每次覆盖都写入 `events` 表，`type = safety_override`，记录规则编号。
- **兜底触发率**本身是评估指标。S3 的保守参数决定了它的触发频率，参数只能在训练集上调。

### 4.5 减少速度损失的手段

1. **超前预测**：早一点、小幅地降，代替晚一点、大幅地降。电池焦耳热 ∝ I²，产热是功率的凸函数。按 Jensen 不等式，平均功率相同时，平稳的功率曲线产热更少。
2. **识别 Sink 自我节流**：合约不变但 `p_in` 自主下降，且不符合 CV 阶段的衰减形态时，判定 Sink 在自我节流。由派生特征 `self_throttle_score` 表示，作为 B 的输入特征之一，只能由白名单字段计算。训练该检测器时可以用 `sink_tm_active` 作为目标。
3. **感知需求**：当 P̂_dem 小于顶端 PDO 的功率时，收紧游标没有速度代价。
4. **可选**：MPC 与贪心截断的对比（T1.11）；功率预算游标 C-PB。

## 5. 理论要点

论文中给出以下结论，并附简短证明。

**引理 1（安全性与 Sink 选择规则无关）**：令 R(S) = max_{p∈S} r(p)。对任意选择规则 g，都有 r(g(S)) ≤ R(S)。因此只要 R(S(k*)) ≤ τ，无论 Sink 选哪个 PDO，风险都不超过 τ。
证明：g(S) ∈ S，取最大值的定义即得。

**引理 2（单调轴下的计算简化）**：如果沿排序轴 r(p_i) 单调不减，则 R(S(c)) = r(p_c)。此时可行游标集合 {c : R(S(c)) ≤ τ} 是一个前缀 {1, …, k*}，可以用二分查找。

**命题 3（帕累托链截断的速度最优性）**：删除被支配的 PDO 后，沿轴的速度 s 和风险 r 同时单调不减。此时，在所有包含 p_1 且满足 R(S) ≤ τ 的子集 S 中，S(k*) 能达到的最高速度 max_{p∈S} s(p) 最大。
证明要点：任取一个安全集合 S，设 p' 是其中速度最高的 PDO。p' 要么在链上，要么被链上某个 q 支配，满足 s(q) ≥ s(p') 且 r(q) ≤ r(p') ≤ τ。链上风险 ≤ τ 的元素构成前缀，所以 q ∈ S(k*)。∎

**覆盖率保证**：如果校准会话与测试会话可交换，CQR 给出边际覆盖率 P(Y ≤ 上界) ≥ 1 − α。没见过的设备会破坏可交换性，因此必须单独报告 OOD 测试集上的实际覆盖率。

**能量上界**：电池净充电时，Sink 总产热 ≤ `p_in`。边充边重度使用、电池同时放电时，这一上界不成立。论文中要写为局限。

## 6. 实验设计

### 6.1 三类实验平台

| 平台 | 阶段 | 用途 |
|---|---|---|
| 仿真：虚拟 Sink 群体 | 阶段 1 | 大规模对比、消融、Pareto 曲线 |
| 参考 Sink：PD Sink 控制器 + 充电 IC 评估板 + 带保护的锂电芯 + 热电偶 | 阶段 2 | 完全可观测；可编程申请策略和热管理开关；安全地制造过温工况 |

### 6.2 测量的三个层级

| 层级 | 测什么 | 方法 |
|---|---|---|
| 1. 系统上报 | 电池包温度、电流、电压、电量 | Android：`dumpsys battery`、`/sys/class/power_supply/battery/*`、`ACTION_BATTERY_CHANGED`；macOS：`ioreg -rn AppleSmartBattery` |
| 2. 外部测温 | 表面温度、接口温度 | 细规格热电偶 + 多通道记录仪；红外热像仪（被测处贴发射率已知的黑胶带） |
| 3. 参考 Sink | 电芯表面温度、充电 IC 温度 | 热电偶直接贴在电芯和 IC 上 |

Android 采集注意事项：
- USB 口被 PD Source 占用，用无线调试；或用转接板把 PC 的 D+/D- 与 Source 的 VBUS/CC 合并。
- 屏幕关闭，开飞行模式（无线调试时只保留 Wi-Fi）。
- 关闭自适应充电、"充到 80% 停止"之类的功能。

### 6.3 场景矩阵（默认值，人类可改）

| 维度 | 取值 |
|---|---|
| 环境温度 | 25°C、35°C、40°C |
| 散热条件 | 裸机、手机壳、覆盖保温物（仿真中 R_sa 乘以 1.0 / 1.5 / 3.0） |

### 6.4 对比方法（控制器）

| 编号 | 方法 |
|---|---|
| B0 | 不加限制（全部 PDO 都广播） |
| B1 | 静态降额：固定游标，在训练集上调到最差场景过温率 ≤ α |
| B2 | 反应式阈值：只看 Source 侧温度（`t_src`、`t_con`），超阈值就降档 |
| B3 | 反应式阈值 + PD 3.0 Status 温度（只用于 PD 3.0 Sink，需 Q4 批准） |
| B4 | 纯 RC 模型（M0）+ 同样的 C |
| B5 | 纯黑盒（M1）+ 同样的 C |
| B6 | Oracle：已知真实温度和真实模型，同样的 C |
| B7 | PPS 连续调功参照：只用于支持 PPS 的 Sink，已知真实温度，按功率连续调节（速度上界参照） |
| Ours | M2 + C + 安全兜底 |

### 6.5 指标

- **安全**：
  - 每个节点的过温会话比例；
  - 超限时长；
  - 峰值温度；
  - 最大超限幅度。
- **速度**：
  - 充到 50% / 80% 的时间（t_50、t_80）；
  - 前 30 分钟交付的能量；
  - 速度损失 L；
  - 相对 oracle 的 regret。
- **协议**：
  - 每小时重新协商次数；
  - Hard Reset 次数；
  - 协商失败次数。
- **兜底**：兜底层触发率（按规则分别统计）。
- **预测质量**：
  - 各分位数的 pinball loss；
  - 实际覆盖率与名义覆盖率对比，分 IID 和 OOD 两组；
  - 最高温度的 MAE。
- **部署开销**：参数量、int8 模型大小、MCU 上的推理时间和内存。
- **统计方法**：均值 ± 95% 置信区间（按设备 bootstrap）。

## 8. 表述规范【已定】

| 不要写 | 英文论文中不要写 | 改为 |
|---|---|---|
| 零过温 / 保证不过温 | zero overheating / guarantees no overheating | 在机会约束 P(过温) ≤ α 下控制风险；兜底层基于物理上界（chance-constrained; physics-based safety fallback） |
| 帕累托最优 | Pareto-optimal / Pareto optimality | 逼近安全–速度帕累托前沿（approaches the safety–speed Pareto frontier） |
| Sink 没有热管理 / 盲目申请最高功率 | sinks lack thermal management / blindly request maximum power | Source 无法获知或信任 Sink 的热管理（the source cannot know or trust the sink's thermal management） |
| PINN 预测出的风险就是真实风险 | the predicted risk is the true risk | 经校准的风险上界估计（calibrated upper-bound estimate of risk） |
| 适用于所有设备 | works for all devices | 在测试的 N 类、M 台设备上验证（validated on N classes, M devices） |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 盲 Sink 的温度不可观测，对没见过的设备泛化差 | 单独设置 OOD 测试集；使用设备先验；兜底层 S3 |
| 边充边重度使用时能量上界失效 | 写为局限；仿真中专门测试这一场景并报告 |
| 老设备不能正常处理重新协商 | 兼容性测试（T2.4）；滞回和最小驻留时间降低协商频率；把 Hard Reset 次数列为指标 |
| 动态缩减能力与 Power Rules 认证的关系 | 在论文中讨论；以多口充电器的动态分配作为先例；T0.2 核实规范表述 |
| 差异化不足 | T0.3 系统检索：充电器侧温控产品、多口动态分配、BMS 最优快充、手机热管理 |
| 仿真种群与真实设备差距大 | 用参考 Sink 和商用设备数据做 sim-to-real；报告差距 |
